# Guild Marketing OS Answer Engine And Web Readiness Method

Status: live private

Use when a Guild Marketing OS agent needs to evaluate or draft website, AEO, AI-readiness, schema, `llms.txt`, content architecture, or answer-ready recommendations from approved project context.

## Method

1. Confirm the approved entity facts: project name, category, canonical URL, description, audience, proof-backed claims, and no-go claims.
2. Identify the priority questions the project should answer for humans, search engines, and AI assistants.
3. Review current web inputs when supplied: pages, docs, metadata, schema, robots rules, sitemap, FAQs, comparison pages, proof pages, and canonical profiles.
4. Separate visibility observations from recommendations and unknowns.
5. Draft extractable answer blocks only from approved entity facts and evidence.
6. Recommend web, schema, metadata, content, and source improvements without claiming deployment or guaranteed visibility.
7. Maintain a priority query set with intent, primary surface, minimum proof anchors, and review cadence.
8. Route missing proof, missing entity facts, and technical deployment work to the right owner.

## Readiness Checks

- Entity clarity: name, category, canonical URL, ownership, and relationship to related projects.
- Answer coverage: what it is, who it serves, why it matters, how it works, when to use it, alternatives, limitations, and proof.
- Extractability: short answer blocks, clear headings, comparison tables, FAQs, examples, and source-backed statistics.
- Authority: approved evidence, named source pages, contributor or maintainer context, case studies, third-party references, and freshness.
- Fit clarity: who the project, company, or offer is for, who it is not for, and which alternatives or status-quo options should be named.
- Claim hygiene: inspectable evidence, verification method, last-reviewed date, and do-not-use claims.
- Crawl and index hygiene: canonical URLs, robots policy, sitemap status, page titles, descriptions, headings, and internal links.
- Structured data inputs: Organization, WebSite, Article, SoftwareApplication, FAQPage, HowTo, BreadcrumbList, Event, or other relevant schema candidates.
- Agent-readable inputs: `llms.txt`, docs index, source pages, public project facts, and clear licensing or trademark constraints.
- Zero-click evaluation: answer presence, answer correctness, citation rate, branded or direct demand, inbound quality, and first-conversation fit.

## Output Standard

Every answer-engine and web-readiness packet should include:

- Approved entity facts used.
- Priority audience questions.
- Priority query set with intent, current primary surface, and minimum proof anchors.
- Current visibility or web evidence reviewed.
- Answer-ready blocks with claim status.
- Claims and evidence table with verification method and last-reviewed date.
- Schema and metadata recommendations.
- `llms.txt` or agent-readable source recommendations.
- Zero-click scorecard and freshness recommendations when relevant.
- Site architecture and internal-linking recommendations when relevant.
- Missing proof, missing source pages, and deployment blockers.
- Approval decisions required before publication.

## Handoff Targets

- Messaging receives answer-ready blocks and entity-language gaps.
- Branding And Pitch Deck receives web narrative and brand-system implications.
- Market Signal receives external citation, competitor, and search-signal gaps.
- Campaigns And Paid Media receives landing-page clarity, FAQ, proof, and destination gaps.
- Company Context Builder receives updates to project context, messaging source, proof constraints, and channel registry.
- Dashboard Signals receives answer presence, answer correctness, citation, freshness, and inbound-fit fields.

## Claim Rules

Do not claim AI citations, rankings, rich results, schema deployment, crawler access, or production website changes unless an approved source or tool confirms them. Treat AI-search recommendations as readiness work, not guaranteed outcomes.
